# Management & Cognitive Models Behind the Rules

Read this file to understand why the rules exist, or to adapt them to a new platform. v3 balances classic operational discipline with **cognitive science and swarm intelligence** so structure never suffocates agent intelligence.

| Source | Idea | Applied as | Guardrail against over-constraint |
|---|---|---|---|
| **Mission command (*Auftragstaktik*)** | Give intent and boundaries, never step-by-step recipes | Three Brief Modes (`tight`, `guided`, `exploratory`); state *what* and *why*, not *how* | Explicit **Premise Challenge Right**: workers must push back (`assumptions_challenged`) when ground truth contradicts the manager's brief |
| **Stigmergy & Blackboard Systems (Swarm Intelligence)** | Agents coordinate indirectly by leaving rich traces in a shared environment rather than routing every byte through a central bottleneck | **Shared Blackboard** (`--context-file` / `.orch/` artifacts) and `handoff_notes` | Prevents "lossy manager relay" (where a manager summarizes Worker A's 10-page finding into 3 sentences and drops the key edge case for Worker B) |
| **Sensemaking & Cynefin Framework (Snowden)** | Ordered domains fit checklists (`tight`/`guided`); complex/chaotic domains need open probing (`exploratory`) | Brief Mode selection in Gate 1 & `route.py` | Never force an exploratory debugging or research task into a rigid Definition of Done before the territory is mapped |
| **Hegelian Dialectic & Constructive Controversy** | Thesis + Antithesis → **Synthesis (Option C)**, settled by empirical tests rather than rhetoric | Huddle Step 3 (**Empirical Spike Gate**) and Step 4 (**Dialectical Synthesis**) | Panelists are asked to transcend trade-offs into a better Option C, and testable factual cruxes are settled by a 2-minute code spike instead of debate |
| **Epistemic Diversity (Hong & Page)** | Diverse cognitive architectures outperform homogeneous groups of high-ability clones | Model-family routing (`openai` vs `google` vs `anthropic`) and distinct lenses (`roles.md`) | Roles are defined as **lenses (a floor, not a ceiling)**—never as blinders that forbid noticing adjacent defects |
| **Andy Grove, *High Output Management*** | Supervision depends on task-relevant maturity; catch defects at the cheapest stage | Verification levels (L0–L3) + Earned Autonomy in `ledger.jsonl` | Automatic task canonicalization (`canonical_task`) and tier inference (`infer_tier`) so real-world runs always feed the learning loop |
| **Amazon single-threaded owner & Type 1/Type 2** | One owner per write scope; irreversible decisions get deep care, reversible ones get speed | Write-scope attribution (`--may-write`) or isolated worktrees (`Workspace: "branch"\|"share"`, `--worktree`) | Parallel intelligence is encouraged; parallel writes use isolated worktrees/branches rather than blocking collaboration |
| **Toyota *jidoka* / Andon** | Any worker may stop the line when an anomaly or flawed premise appears | `stopped` status + `assumptions_challenged` in `result.schema.json` | Pulling andon when a brief's premise is wrong is rewarded as a successful discovery, not treated as a worker failure |

## Empirical evidence from multi-agent systems (2025–2026)
- **Token economics:** Multi-agent runs spend ~5x–15x the tokens of single-turn chat, and external CLI invocations carry ~12.5k (`codex`) to ~19.5k (`agy`) fixed token overhead. Use native subagents (`Agent`, `invoke_subagent`, `spawn_agent`) and `tight` briefs for small tasks.
- **Clean-context cross-family review:** A reviewer from a different model family with a clean context (reading the diff and upstream artifact directly via `--context-file`) consistently catches methodological and logic flaws that the builder model rationalizes away (confirmed in real `ledger.jsonl` runs on `GRACE-CLIP`).
- **Premise falsification in scientific/ML workflows:** In real debugging and research runs, the highest-value agent contributions came when the reviewer or investigator tested the manager's assumption (e.g., RNG state leakage across optional modules, asymmetric optimization schedules) rather than merely checking off a preset list.
